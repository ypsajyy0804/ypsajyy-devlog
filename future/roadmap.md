## 0. 先做一次现实检查（必须读）

**20 小时/周 × 16 周 = 320 小时**，分到 5 条线：

| 科目 | 占比 | 周时长 | 学期总量 | 这个总量够干什么 |
|---|---|---|---|---|
| C | 30% | 6h | 96h | 够从零到「能手写链表/哈希表/内存池，会用 gdb + valgrind 自查内存」 |
| Java | 20% | 4h | 64h | 够「补完基础 + 集合框架 + 回填实习项目」，**不够**系统学 JVM |
| Linux | 20% | 4h | 64h | 够「命令行熟练 + shell 脚本 + 系统编程入门（fork/exec/信号/管道）」 |
| 数据结构 | 20% | 4h | 64h | 够「线性表/树/图/排序全过一遍 + LeetCode 60 题」 |
| 网络 / OS | 10% | 2h | 32h | 够「看懂 TCP/IP 分层 + 进程线程内存管理概念」，**不够**深入 |

**三条你必须提前接受的现实：**

1. **这不是「同时学 5 样」，是「1 条主线 + 4 条辅线」。** 主线是 **C**（占 30% 且和数据结构、Linux 系统编程高度重叠，实际有效时间超过 96h）。别把 5 科平均用力。
2. **网络 / OS 这学期只配 32 小时，注定是「建立概念 + 留坑」。** 这是故意的 —— 真正的网络会在下学期 Socket / epoll 那里补回来，OS 会在 C++ 多线程 / 内存管理那里补回来。这一轮的目标是**看懂术语，不是掌握机制**。
3. **Java 那 20% 不是为了精进 Java，是为了「止损」。** 详见 §2。

## 1. 每周固定时间模板（20h）

不要每天切 5 科 —— 大脑切换成本会吃掉一半效率。**按「主题日」排**：

| 时段 | 时长 | 科目 | 干什么 |
|---|---|---|---|
| 周一 晚 | 2h | **C** | 看书 + 写代码（学 1 练 1） |
| 周二 晚 | 2h | **数据结构** | 概念 + **用 C 手写实现** |
| 周三 晚 | 2h | **Linux** | 命令行 / shell，**必须在真实终端里敲** |
| 周四 晚 | 2h | **C** | 补周一没写完的题 + 复现上周的坑 |
| 周五 晚 | 2h | **Java** | 见 §2 的分工 |
| 周六 | 5h | C(2) + 数据结构(2) + 网络/OS(1) | 整天块：连写代码 + LeetCode 3 题 |
| 周日 | 5h | Linux(2) + Java(2) + 网络/OS(1) | 复盘 + 写笔记 + 补欠账 |

**每周汇总**：C 6h ｜ 数据结构 4h ｜ Linux 4h ｜ Java 4h ｜ 网络/OS 2h = **20h** ✓

**每个主题日开工前，先打开 [`exercises/`](../present/exercises/) 里本周的清单**，照着题目写。清单没覆盖到的，自己加。写完拿来审（流程见 [`CLAUDE.md`](../CLAUDE.md) §3）。

> **红线 1**：这 20 小时**不含**课内作业和课程复习。期末周（W15-W16）允许砍到 8h/周，但**不许断**——断了就再也起不来。
>
> **红线 2**：**看视频/看书不算完成。** 只有代码写出来了、跑通了、能解释了，才算。这条是 2026-10-12 加上的，因为前两周证明了「只输入、不输出」可以持续很久而不产生任何能力。

## 2. Java 这 20% 怎么用（止损策略，不是精进）

你实习那个项目，简历上会写，面试官会问，而你现在**完全看不懂**。这是你未来一年最大的风险点 —— 比 C 学得慢危险得多。

**Java 时段 = 三件事，按优先级：**

1. **回填实习项目（最高优先级，投入 8-10 周）**
   把当时 agent 生成的代码重新翻出来，逐层问自己：
   - Controller 收到请求后，第一个进的是哪个类？靠什么路由过去的？（答：`@RequestMapping` → `DispatcherServlet`）
   - Service 层的方法凭什么能被 Controller 调到？（答：Spring 容器 + `@Autowired` 依赖注入）
   - Mapper 是怎么变成能执行的 SQL 的？（答：MyBatis 动态代理 + XML/注解）
   - 事务是在哪一层加的？为什么加在 Service 不加在 Controller？
   - 一个请求从进来到返回，完整链路画得出来吗？
   - **目标：能在一张 A4 纸上画出这个项目的完整请求链路图。画不出来就是没回填完。**
2. **补基础概念（每周 1h）**
   集合框架（`ArrayList` vs `LinkedList` vs `HashMap` 扩容）、`equals`/`hashCode` 契约、异常体系、`synchronized` / `volatile`、JVM 内存区域（堆/栈/方法区）、GC 基本概念。
3. **不做的**：不要再去学 Spring Cloud / 微服务 / 新框架。**这 20% 只用来止损和能讲清楚，不用来堆新技术栈。**
