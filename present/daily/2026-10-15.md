## 定向学习 · gdb 的 4 个命令（25 分钟）

**不是学 gdb 的全貌，就这 4 个：**

| 命令 | 干什么 |
|---|---|
| `run` | 跑程序，停在崩溃处 |
| `bt` | backtrace —— 崩溃点在哪一层调用 |
| `info proc mappings` | 这个进程的**内存段表**（今天的主角） |
| `x/s 地址` | 按字符串看一块内存 |

**为什么是这 4 个**：`CLAUDE.md` §11 那句「面试时能从内存层面讲清楚每一行」——
`bt` 和 `info proc mappings` 就是那把尺子。后面所有的段错误、内存泄漏、越界都靠它们。

**装**：

```
sudo apt install -y gdb
gdb --version
```

> 装工具属于环境配置，不走提示阶梯 —— 直接抄上面的命令。

**验收**：合上这份文档，能说出 `bt` 和 `info proc mappings` 各解决什么问题。

## 任务 2 · 收 A02 的账（20 分钟）

> 这题你卡了 3 轮（施工单里问过 → 对话里指过 → 你说找不到）。按 `CLAUDE.md` §6 第 4 条，我直接给。

**错在哪**

```
printf("%ld\n", sizeof(char));
```

`%ld` 要的是 `long`。而 `sizeof` 返回的是 `size_t`。**两个不是同一个类型。**

**为什么 gcc 一声不吭**

`-Wformat` **默认不检查有符号 / 无符号是否匹配** —— 要显式加 `-Wformat-signedness` 才会报。
我上次说它「很可能编不过」，是我判断错了。

**为什么还是必须改**

| 平台 | `long` | `size_t` | `%ld` 打印 `sizeof` 的结果 |
|---|---|---|---|
| Linux x86-64 (LP64) | 8 | 8 | 碰巧对 —— 小数值恰好一样 |
| Windows x86-64 (LLP64) | **4** | **8** | **只读 4 字节，打印出垃圾** |

C 标准要求格式符和实参类型严格匹配，不匹配就是 undefined behavior。
「碰巧对」不是「对」—— 这正是你昨天在 `A01` 里想学的那类东西。

**正确写法**：`%zu`

### 变体练习（必须做，做完贴回来审）

**先写下你的预测，再跑。** 不要跑完倒推。

```c
printf("%zu\n", sizeof(int));
printf("%ld\n", (long)sizeof(int));
printf("%d\n",  sizeof(int));
```

问题：三个数分别是多少？**第 3 行在 64 位 Linux 上打出的是几？为什么它和上面两个不一样？**
（提示：`int` 是 4 字节，但如果 `%d` 只读了 4 字节而实际压进去 8 字节，会发生什么）
