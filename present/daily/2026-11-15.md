## 定向学习 · `make` 到底怎么看得出该重编谁（20 分钟）

新建 `present/code/c/mk/`，放三个文件。

`util.h`：

```c
#ifndef UTIL_H
#define UTIL_H

int add(int a, int b);

#endif
```

`util.c`：

```c
#include "util.h"

int add(int a, int b) { return a + b; }
```

`main.c`：

```c
#include <stdio.h>
#include "util.h"

int main(void) {
    printf("%d\n", add(2, 3));
    return 0;
}
```

`Makefile`（注意：下面每行命令前面是 **Tab**，不是空格）：

```make
CC = gcc
CFLAGS = -Wall -Wextra -Werror

build/mkapp: build/main.o build/util.o | build
	$(CC) $(CFLAGS) -o $@ $^

build/main.o: main.c util.h | build
	$(CC) $(CFLAGS) -c main.c -o $@

build/util.o: util.c util.h | build
	$(CC) $(CFLAGS) -c util.c -o $@

build:
	mkdir -p build

clean:
	rm -rf build

.PHONY: clean
```

### 三步实验（每步都 `make`，记下它编了什么）

1. 第一次 `make` —— 输出里出现几次 `gcc`？
2. 再 `make` 一次，什么都不改 —— 输出什么？
3. 改 `util.h`（加个空行，比如多按一次回车），再 `make` —— **哪些 `.o` 被重编了？`main.c` 和 `util.c` 都没改，为什么 `main.o` 也要重编？**

### 三问

1. 第 2 步 `make` 输出 `make: 'build/mkapp' is up to date.`，它是**怎么知道的**？比的是什么？
2. 第 3 步为什么两个 `.o` 都重编了？如果 `Makefile` 里 `build/main.o` 这条规则只写 `main.c`、不写 `util.h`，第 3 步会怎样？
3. `build:` 那条规则没有命令产出叫 `build` 的文件（是个目录）。为什么第二次 `make` 不会因为「`build` 比 `.o` 旧」而重新执行它？（提示：目录的修改时间什么时候会变）

## 任务 1 · 把 `recdb` 拆成三个文件（45 分钟）

**目录**：`present/code/c/recdb_proj/`，**五个文件**。

### `recdb.h` —— 你来写

里面必须只有这几样：

```c
struct Rec { int id; char name[16]; double score; };

int  rec_write(const char *path);                              /* 文件不存在才写，返回写了几条 */
int  rec_show (const char *path);                              /* 打印全部，返回条数 */
int  rec_patch(const char *path, int id, double score);        /* 改一条，返回 1 成功 / 0 没找到 */
```

外加**头文件保护**（`#ifndef` / `#define` / `#endif`）。

### `recdb.c` —— 你来写

上面三个函数的实现，从你 11-14 的 `recdb.c` 搬过来，改三处：

1. **`rec_show` 不许再写死「3 条」** —— 用 `fread` 的返回值判断读到几条，读到几条打几条。
2. **`rec_show` 里 `fread` 的返回值必须检查**，读不出来要能看出来（打一行 `read error`，返回 0）。
3. 不再 `printf` 用法错误提示 —— 提示归 `main.c`。

### `main.c` —— 你来写

只做参数解析和调函数，保持和 11-14 一样的命令行用法和**逐字一样的输出**。

### `Makefile` —— 你来写

- `make` 产出 `build/recdb`
- 每个 `.c` 单独编成 `.o`，`recdb.c` 和 `main.c` 都依赖 `recdb.h`
- `make clean` 删掉 `build/`
- 不写 `build/` 目录就 `mkdir -p`

### 验收（三条）

- `make` 一次成功，零警告，产出 `build/recdb`
- 四条命令的输出和你 11-14 交的**逐字一致**（含 `exists, skip`）
- `make clean && make` 也能一次成功
