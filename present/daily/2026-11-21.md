## 定向学习 · 一个改不动的 head（20 分钟）

新建 `present/code/c/del_head.c`，照抄（诊断实验）。

```c
#include <stdio.h>
#include <stdlib.h>

typedef struct N { int v; struct N *next; } N;

void del_head(N *head) {
    if (head == NULL) return;
    head = head->next;
}

int main(void) {
    N *a = malloc(sizeof(N));
    N *b = malloc(sizeof(N));
    a->v = 1; a->next = b;
    b->v = 2; b->next = NULL;

    del_head(a);

    printf("main 里的 a 指向: %d\n", a->v);

    free(a);
    free(b);
    return 0;
}
```

`gcc -Wall -Wextra -o build/del_head del_head.c && ./build/del_head`

应该打出：

```
main 里的 a 指向: 1
```

### 三问

1. `del_head` 里第 8 行 `head = head->next;` 到底改了谁？为什么 `main` 里的 `a` 一点没动？
2. 要让 `main` 里的 `a` 也变成 `b`，**在不改 `main` 的前提下**，`del_head` 的参数类型该怎么写？写出新的签名。
3. 删**链表中间**的节点时，需不需要动 `main` 里那个 `a`？那需要动的是什么？（想清楚这两问，`ht_del` 就写出来了）

## 任务 1 · 给 `ht.c` 加 `ht_del`（50 分钟）

**文件**：`present/code/c/ht.c`（在昨天那份上改，不要新建）。

新增一个函数，签名照给：

```c
int ht_del(HT *h, const char *key);
```

规格写死：

| 项 | 要求 |
|---|---|
| 找到并删掉 | 返回 `1` |
| 没找到 | 返回 `0`，哈希表**一个字节都不许变** |
| 必须释放 | 那个节点的 `key`（`strdup` 出来的那块）**和**节点本身 —— **两块，不是一块** |
| `size` | 删成功时减一 |
| 删完桶变空 | 桶里那个指针必须变回 `NULL`，不许留悬空指针 |

### `main` 里在原有输出之后，追加这五行

```c
printf("del one = %d\n", ht_del(h, "one"));
printf("del one again = %d\n", ht_del(h, "one"));
printf("del nope = %d\n", ht_del(h, "nope"));
printf("count = %u\n", ht_count(h));

/* 把剩下的全删掉 */
const char *rest[9] = {"two","three","four","five","six","seven","eight","nine","ten"};
for (int i = 0; i < 9; i++) ht_del(h, rest[i]);
printf("after delete all: count = %u\n", ht_count(h));
```

### 期望输出（逐字，九行）

```
10/10 ok
eleven: not found
put three again = 0
three = 99, count = 10
del one = 1
del one again = 0
del nope = 0
count = 9
after delete all: count = 0
```

> 注意 `del one again = 0` 之后 `count` 还是 9 —— 删不存在的东西必须什么都不改。

### 必须回答

1. 成功删掉一条记录，你一共 `free` 了几块内存？**分别是什么**？
2. 删「桶里第一条」和删「桶里第三条」，你的代码走的是同一条路径，还是两条？如果是两条，**分界条件**是什么？

### 第二步：valgrind

```bash
valgrind --leak-check=full ./build/ht
```

结尾必须是：

```
All heap blocks were freed -- no leaks are possible
ERROR SUMMARY: 0 errors from 0 contexts
```

> 这一条是今天最硬的验收。**`ht_del` 少 `free` 一块，valgrind 就会报；`ht_del` 多 `free` 一次，valgrind 会报 `Invalid free`。** 两种错都躲不过去。
