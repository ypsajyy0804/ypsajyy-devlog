### 0.2 你用了两个编译器，其中一个不对

`code/c/` 里现在躺着这些：

```
A01.ilk  A01.pdb  A01.obj  A01.exe     A02.ilk  A02.pdb  A02.obj  A02.exe     vc140.pdb     a.out
```

`.ilk` `.pdb` `.obj` `.exe` 是 **MSVC（Visual Studio）** 的产物 —— 你在 Windows 上用 VS Code 直接编译了。
`a.out` 是 **gcc** 的产物 —— 你也跑过一次 gcc。

**两个编译器会给同一种类型报出不同的字节数。** 你在 `A02.c` 里写 `long` 是 4，那是 Windows 的答案：

| 类型 | Windows (MSVC) | Linux (gcc x86-64) |
|---|---|---|
| `int` | 4 | 4 |
| `long` | **4** | **8** |
| 指针 | 8 | 8 |

Windows 用的模型叫 **LLP64**，Linux 用的是 **LP64** —— 区别就在 `long` 是多少位。

你要去的是 Linux / 服务端方向，所以 **`A02` 的数字从今天起一律以 WSL 里 gcc 的输出为准**。
这不是细节：`long` 在两边差一倍，是真实的跨平台 bug 来源，也是面试里会问的东西。
