# daily / —— 每日施工单

## 这是什么

**不是计划，是当天的施工单。**

`future/roadmap.md` 说「这周学 C」，`exercises/2026-W03.md` 说「这周做 A01–A08」——
但「这周」太大了，大到每天坐下来的时候不知道手该放哪。这一层专门解决那个缝隙：
**每天一份，写清楚今天这三道题、每道做多久、做完怎么算过。**

## 目录

| 文件 | 谁写 | 说明 |
|---|---|---|
| `YYYY-MM-DD.md` | 我（Claude）写 | 当天的源文件。你也能改 |
| `YYYY-MM-DD.docx` | `_make.py` 生成 | 打开、打印、直接勾的就是这份 |
| `_make.py` | — | 生成器，只用标准库。你不用动它 |

## 怎么用

1. 打开当天的 `.docx`（Word / WPS / 手机都能开）
2. **按顺序做，不跳题**。做不完就停，在验收区如实划掉
3. 做完在文档里勾 `☐`，并按最后一节「交付格式」把结果贴回对话
4. 我按 `CLAUDE.md` §3 的审查流程走：先问你三个问题，再给自查清单，最后只说最严重的一个问题

「交付格式」那一段是这套机制的关键 —— 它规定了**你交什么**。
没有交付格式的任务清单，等于没有任务清单。

## 三条规矩

**1. 一天一份，过期不补。**
昨天没做的，不搬到今天。今天做今天的。堆积的欠账只会让下次更不想打开。

**2. 每天按 90–120 分钟设计。**
做不完是预期内的，做完了如实记「做完了」，没做完也如实记。空着比撒谎有用。

**3. 这里不会出现「看视频」「读书」。**
所有任务的验收标准都是 **「代码跑出来了 + 能解释」**。
看视频和读书不算——这条是 2026-10-12 立的，因为前两周证明了「只输入不输出」可以持续很久而不产生任何能力。

## 怎么生成 docx

```bash
python present/daily/_make.py                # 补齐所有缺的 docx
python present/daily/_make.py 2026-10-13     # 只生成某天
python present/daily/_make.py --force        # 全部重新生成
```

改了 `.md` 要重新跑一次，`.docx` 才会更新。

生成器支持的 markdown 子集很小：标题、代码块、列表、`- [ ]` 复选框、引用、`---`、
管道表格、`**粗体**`、`` `行内代码` ``。别的语法它不认，会当成普通段落。

> 之所以自己写生成器而不是 `pip install python-docx`：本机 PyPI 连不上。
> docx 本质就是个 zip 包 + 几个 XML，用标准库 `zipfile` 直接拼就行。
