# daily / —— 每日施工单

## 这是什么

**不是计划，是当天的施工单。**

`future/roadmap.md` 说「这周学 C」，`exercises/2026-W03.md` 说「这周做 A01–A08」——
但「这周」太大了，大到每天坐下来的时候不知道手该放哪。这一层专门解决那个缝隙：
**每天一份，写清楚今天这三道题、每道做多久、做完怎么算过。**

## 目录

| 文件 | 谁写 | 说明 |
|---|---|---|
| `YYYY-MM-DD.md` | 我（Claude）写 | 当天的源文件。你也能改 |
| `YYYY-MM-DD.docx` | `_make.py` 生成 | 打开、打印、直接勾的就是这份 |
| `_make.py` | — | 生成器，只用标准库。你不用动它 |

## 怎么用

1. 打开当天的 `.docx`（Word / WPS / 手机都能开）
2. **按顺序做，不跳题**。做不完就停，在验收区如实划掉
3. 做完在文档里勾 `☐`，并按最后一节「交付格式」把结果贴回对话
4. 我按 `CLAUDE.md` §3 的审查流程走：先问你三个问题，再给自查清单，最后只说最严重的一个问题

「交付格式」那一段是这套机制的关键 —— 它规定了**你交什么**。
没有交付格式的任务清单，等于没有任务清单。

## 三条规矩

**1. 一天一份，过期不补。**
昨天没做的，不搬到今天。今天做今天的。堆积的欠账只会让下次更不想打开。

**2. 每天按 90–120 分钟设计。**
做不完是预期内的，做完了如实记「做完了」，没做完也如实记。空着比撒谎有用。

**3. 这里不会出现「看视频」「读书」。**
所有任务的验收标准都是 **「代码跑出来了 + 能解释」**。
看视频和读书不算——这条是 2026-10-12 立的，因为前两周证明了「只输入不输出」可以持续很久而不产生任何能力。

**4. 但每份的第一段是「定向学习」（2026-10-14 加）。**
他当天提的：「就不能抽一些时间，给一些任务指挥我去学一些针对性的具体任务吗？没足够的知识储备，写这几个破题效率根本不可能高到哪里去。」

所以每份施工单固定结构：

| 段 | 内容 | 谁定 |
|---|---|---|
| 定向学习 | 指定**具体**东西：工具、man 页、4 个命令、一个概念。**限时、给验收** | 我定 |
| 任务 1–N | 动手题 | 我定 |
| 收尾 | 笔记 / 记录 | 我定 |

**「定向学习」不等于「去看视频」。** 它必须满足两条：
1. **内容具体到可勾选** —— 「学 epoll」不合格，「学会 epoll 的 4 个系统调用参数」合格
2. **后面必须跟一个动手任务去用它** —— 学完 gdb 就立刻用它抓一个真实的段错误

否则它就退化成前两周那种「只输入不输出」，那是已经证明失败过的模式。

**5. 涉及外部依赖的验收，必须有一条「依赖坏了它必然失败」的动作（2026-10-23 加）。**

10-23 的 J03 环境搭建，验收写的是 `Tomcat started on port 8080`。
可 Spring Boot 的 `DataSource` 是懒连接 —— 只要没有一句代码真去用数据库，
端口写错、`mybatis` 缩进错、密码写错，**全都照样启动成功**。
他按我的标准宣布「环境搭好了」，而数据库一次都没被碰过。**这是施工单的设计缺陷，不是他的执行问题。**

规矩：验收项里至少一条，**在依赖坏掉时必然失败**。

| 依赖 | 不合格的验收 | 合格的验收 |
|---|---|---|
| 数据库 | 「应用起来了」 | 启动时跑一句 `SELECT 1`，连不上就起不来 |
| HTTP 服务 | 「进程在跑」 | 一条 `curl` 拿到 200 和预期 body |
| 端口 | 「没报错」 | `ss -tlnp \| grep 8080` 能看到 LISTEN |

**6. 直接给的代码，只能用他已经有的概念拼（2026-10-23 加）。**

同一天我还犯了第二个错：打着 §6「环境配置直接给」的旗号，
给了一段含 `@Bean` / `CommandLineRunner` / 依赖注入的探针代码。
那不是工具链语法，是 Spring 容器的概念 —— 他根本没有这个概念。

他的话：「我懵里懵懂地把代码 copy 上去、运行，可是我根本不懂这个 `@Bean` 到底做了什么。」

§6 的「环境配置直接给」指的是：**装什么、填哪个路径、命令行怎么敲**。
凡是代码里出现他还没学过的语言/框架特性（`@Bean`、`@Autowired`、`@Transactional`……），
要么换一条不依赖它的路（例如纯 JDBC 的 `DriverManager`），要么先让他自己写一遍。

**7. 写代码的任务，题面必须写死六样东西（2026-10-24 加）。**

他 10-24 的原话：

> 「像 V03.c V04.c 以及之前的 vector.c 等等手写代码的题目，我大量的时间花在揣测你的题目意思上，
> 你的题目写得太简陋、让人一看就懵了！」
> 「'vector.c' 'V03.c' 'V04.c' 等等在任务里的写法不是误导我要分别独立写成 C 程序代码吗？我不认这点。」

**核对结果：他对。** 10-19 / 10-20 的施工单写了「主角文件 `code/c/vector.c`」，
10-24 的任务 1/2 只写了「任务 1 · V03 `reserve` 与 `resize`」，**没写文件名**；
可 `exercises/2026-W04.md` 里的 `P04a.c` / `P04b.c` 又建立了「编号 = 文件名」的惯例。
两套惯例混着用，他按多数那套猜，猜错了不能记在他头上。

| # | 要素 | 反例 | 正例 |
|---|---|---|---|
| 1 | **文件名** | 「写 V03」 | 「写进 `code/c/vector.c`，不要新建文件」 |
| 2 | **函数签名** | 「实现 insert」 | 「`void vec_insert(Vec *v, size_t pos, int x);`」 |
| 3 | **具体输入** | 「测一下插入」 | 「在 `{1,2,3,4}` 上 `vec_insert(v, 2, 9)`」 |
| 4 | **逐字期望输出** | 「应该能打出来」 | 「必须打出 `1 2 9 3 4`，一个字符不差」 |
| 5 | **交付物** | 「做完告诉我」 | 「代码 + 编译命令 + 运行输出」 |
| 6 | **不许留猜的余地** | 「你自己想想这是什么」 | 见 1–5 |

**判据：如果他需要花时间去揣测「这题到底要我做什么」，那就是题面的缺陷，不是他的问题。**
他为了猜我的意思，10-24 花了 5 小时做完计划 100 分钟的量 —— 多出来的时间全在这里。

**8. 一份施工单最多 1 个新概念（2026-10-24 加）。**

他 10-24 的原话：

> 「你给我计划的是大概 1~2h 就可以完成，但我每天基本都要花上 3~4 小时才能完成，
> 因为任务里很多都与我来说的某个新概念、我没见过的代码写法，有时候就真的是一抓一大把，
> 我要花大量的时间去问 chatgpt，花大量的时间去看 gpt 生成的文字来理解你布置的任务、新概念、没见过的代码写法。」

**核对属实。根因是我的估时是按「我自己写这段要多久」算的，不是按他算的。**
他脑子里没有那些东西，所以每碰到一个，就要停 30–40 分钟。

四条规矩：

1. **一份施工单里，他没见过的概念最多 1 个。** 其余所有东西必须用他已经会的拼。
   （判据：翻 `present/code/` 和 `progress.md`，这东西他写过没有。）
2. **新概念入场方式**：给 ≤10 行**能跑**的例子 + 一个问题，**不要给文字解释**。
   跑完他说输出，我再判断他懂没懂。
3. **估时公式**：`任务数 × 20 分钟 + 新概念数 × 35 分钟`。超过 120 分钟就砍任务，不是砍标准。
   而且这个数字要标成「**给你的估时**」，不是我的。
4. **题面要自足**：他读完不该再去问第二个 AI。如果还得去问，就是题面没写够。

## 怎么生成 docx

```bash
python present/daily/_make.py                # 补齐所有缺的 docx
python present/daily/_make.py 2026-10-13     # 只生成某天
python present/daily/_make.py --force        # 全部重新生成
```

改了 `.md` 要重新跑一次，`.docx` 才会更新。

> **你在 Word 里勾的框不会被覆盖。** 脚本只在 `.md` 比 `.docx` 新的时候才重新生成 ——
> 所以你打开、勾选、保存之后，那份 docx 就定型了。
> （反过来说：**如果某天改了 `.md`，别加 `--force`**，会把你勾过的记录冲掉。）

生成器支持的 markdown 子集很小：标题、代码块、列表、`- [ ]` 复选框、引用、`---`、
管道表格、`**粗体**`、`` `行内代码` ``。别的语法它不认，会当成普通段落。

> 之所以自己写生成器而不是 `pip install python-docx`：本机 PyPI 连不上。
> docx 本质就是个 zip 包 + 几个 XML，用标准库 `zipfile` 直接拼就行。
