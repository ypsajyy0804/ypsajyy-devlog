## 定向学习 · 让方法自己填状态码（15 分钟）

10-26 那条 `curl /book/1` 返回的是 `200` + **空 body**。查不到书，状态码却是 200 —— 因为你的方法签名是 `public Book`，`Book` 这个类型里没有地方放 `404`。

Spring 给的解法是一个叫 `ResponseEntity` 的类。它和 `List<Book>` 是同一套写法：尖括号里写**body 的类型**。区别是它除了 body，还能装**状态码**。

先看它长什么样。在 `BookController.java` 里加这一个方法（就这一个，别的都别动）：

```java
import org.springframework.http.ResponseEntity;

    @GetMapping("/health")
    public ResponseEntity<String> health() {
        return ResponseEntity.ok("ok");
    }
```

重启，然后：

```bash
curl -v --noproxy '*' http://172.24.48.1:8080/health
```

**验收**：状态行是 `< HTTP/1.1 200`，body 是 `ok`。

**必须回答**：把 `ResponseEntity.ok("ok")` 改成 `ResponseEntity.notFound().build()`，重启再 `curl -v` ——
**`-v` 输出里哪一行变了？body 变成什么？**

## 任务 1 · 循环单链表（40 分钟）

**文件**：`present/code/c/C01.c`（新建，就这一个）

**结构体固定这样**：

```c
typedef struct Node {
    int val;
    struct Node *next;
} Node;
```

**用「尾指针」表示整条循环链表**：`tail` 指向最后一个节点，`tail->next` 回到第一个节点。
空表用 `tail == NULL` 表示。

**必须实现下面这三个函数，就三个，名字和签名一个字都不能改**：

```c
Node *clist_push_back(Node *tail, int v);   /* 在尾部追加，返回新的尾指针 */
void  clist_print(Node *tail);              /* 从第一个节点打印到最后一个节点 */
void  clist_free(Node *tail);               /* 释放全部节点 */
```

**除此之外**：你可以自己加任意辅助函数（比如 `Node *new_node(int v)`），加几个都行、叫什么随你。
判断标准只有一条 —— 上面这三个函数必须存在、签名必须一字不差，并且 `main` 里只能通过它们操作链表。

**`main` 里必须这样调用**：

```c
Node *t = NULL;
t = clist_push_back(t, 1);
t = clist_push_back(t, 2);
t = clist_push_back(t, 3);
t = clist_push_back(t, 4);
clist_print(t);
clist_free(t);
```

**逐字输出**（就这一行，后面紧跟提示符）：

```
1->2->3->4
```

**验收标准**：

- `gcc -g -Wall -Wextra -Werror -o ./build/C01 C01.c` 零警告
- `./build/C01` 输出逐字是 `1->2->3->4`
- `valgrind --leak-check=full ./build/C01` → `All heap blocks were freed -- no leaks are possible`
- 额外自测：**把 `main` 里的四次 push 全注释掉**，`clist_print(t)` 和 `clist_free(t)` 在 `t == NULL` 时不能崩

**必须回答**：

1. `clist_push_back` 收到 `tail == NULL`（空表）时，第一个节点创建出来后，它的 `next` 该指向谁？
2. 为什么整条链表用**尾指针**表示？用头指针的话，`push_back` 每次要做多少步？

## 任务 2 · 把 `/book/{id}` 改成查不到就 404（40 分钟）

`present/code/java/projacts/book-demo/src/main/java/com/environment/test/BookController.java`

**现在**：`seletId` 返回 `Book`，找不到就 `return null` → 200 + 空 body。

**要改成**：返回 `ResponseEntity<Book>`

- 找到了 → **200** + 那本 `Book`
- 没找到 → **404** + 空 body（不再返回 `null`）

**验收标准**：

```bash
curl -v --noproxy '*' -X POST "http://172.24.48.1:8080/book?title=CProgramming&author=me"
curl -v --noproxy '*' http://172.24.48.1:8080/book/1
curl -v --noproxy '*' http://172.24.48.1:8080/book/99
```

- 第 2 条：状态行 `< HTTP/1.1 200`，body 是 `{"id":1,"title":"CProgramming","author":"me"}`
- 第 3 条：状态行 `< HTTP/1.1 404`，body 为空
- 三条 `-v` 输出的状态行都要贴

**必须回答**：同一个方法，为什么改了返回类型之后，状态码就能自己定了？框架是靠什么判断该读你填的状态码，而不是按老规矩给 200？
