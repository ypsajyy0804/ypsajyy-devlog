## 定向学习 · valgrind 的 leak report 怎么读（15 分钟）

```bash
valgrind --leak-check=full --show-leak-kinds=all ./build/vector
```

一份 leak report 只看三处：

1. **`HEAP SUMMARY`** 最后两行 —— `in use at exit` 是多少 bytes
2. **`LEAK SUMMARY`** —— `definitely lost` / `indirectly lost` / `still reachable` 各多少
3. **`definitely lost` 下面那串 `by 0x...: malloc (...)`** —— 那是**你分配内存的那一行**

**验收**：能说出「`definitely lost` 和 `still reachable` 哪个是真泄漏」，以及为什么。

## 任务 1 · 把四个函数并进 `vector.c`（40 分钟）

**文件：`present/code/c/vector.c`，只改这一个文件。**

你现在的状态：`vector.c` 里只有 `vec_init` / `vec_push` / `vec_free`，
`V03.c` 里有 `vec_reserve` / `vec_resize`，`V04.c` 里有 `vec_insert` / `vec_erase`，
三个文件各写了一份 `struct`。今天把它们并成一个。

**并完之后 `vector.c` 里必须有这七个东西，签名一字不改：**

```c
typedef struct { int *data; size_t size; size_t capacity; } Vec;

void vec_init(Vec *v);
void vec_free(Vec *v);
void vec_push(Vec *v, int x);
void vec_reserve(Vec *v, size_t n);
void vec_resize(Vec *v, size_t n);
void vec_insert(Vec *v, size_t pos, int x);
void vec_erase(Vec *v, size_t pos);
```

**`main` 的写法固定**（不要在 `main` 里手写 `malloc(sizeof(vec))` + 手动置三个字段）：

```c
Vec v;
vec_init(&v);
/* ... 用 ... */
vec_free(&v);
```

**跑这三组，输出必须逐字对上：**

| # | 做什么 | 期望输出 |
|---|---|---|
| 1 | 依次 `vec_push(&v, 1..4)`，再 `vec_insert(&v, 2, 9)` | `1 2 9 3 4` |
| 2 | 接着 `vec_erase(&v, 0)` | `2 9 3 4` |
| 3 | 另起一个 `Vec`，`vec_reserve(&w, 100)` 之后 | `capacity = 100`、`size = 0` |

**验收**：`gcc -g -Wall -Wextra -Werror -o build/vector vector.c` 零警告、三组输出对。

**并完之后 `V03.c` / `V04.c` 可以删掉** —— 内容已经在 `vector.c` 里了。
