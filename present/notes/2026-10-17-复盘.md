# 在浏览器里敲下回车之后

> 这篇笔记回答一个问题：**从你在地址栏敲下回车，到页面上出现数据，中间发生了什么？**
>
> 不需要编程基础也能读完。读完之后你会知道，一个网页背后至少有几个程序在互相说话。

---

## 一、先看清楚「请求」长什么样

网页能打开，是因为浏览器向某台电脑**要**东西。这个「要」，用的是一个叫 HTTP 的协议。

HTTP 有一个特点：**它就是一封纯文本的信。** 你能用眼睛读，能手写。

在终端里敲这个命令，就能看到这封信：

```
curl -v http://localhost:8000/
```

`-v` 的意思是「把过程也打印出来」。输出里每一行开头有个符号：

- **`>` 开头的行：浏览器（或者 curl）说的话** —— 请求
- **`<` 开头的行：服务器回的话** —— 响应

真实输出节选：

```
> GET / HTTP/1.1
> Host: localhost:8000
> User-Agent: curl/7.81.0

< HTTP/1.0 200 OK
< Server: SimpleHTTP/0.6 Python/3.10
< Content-Type: text/html
< Content-Length: 1234
```

### 请求的第一行

```
GET / HTTP/1.1
 ↑   ↑    ↑
 │   │    └── 用的是哪个版本的协议
 │   └─────── 我要哪个东西（这里的 / 表示「网站的首页」）
 └─────────── 我要干什么（GET = 取，POST = 提交）
```

### 响应的第一行

```
HTTP/1.0 200 OK
         ↑   ↑
         │   └── 给人看的说明
         └────── 给人（和程序）看的结果代码
```

### `200` 和 `404` 是什么

这两个是**状态码** —— 服务器用一个数字告诉你结果。

| 数字 | 意思 |
|---|---|
| `200` | 找到了，内容在下面 |
| `404` | 你要的那个东西这里没有 |
| `500` | 服务器自己出错了 |

再请求一个不存在的地址：

```
curl -v http://localhost:8000/nothing-here
```

回的就是 `404 File not found`。

**`404` 不是「网络断了」，是「服务器活着，但你要的东西不在」。** 这个区别很重要：
断网你连不上；404 说明对面的程序一切正常，只是查无此物。

## 二、网页上的一句话，可能要两个请求才能凑齐

现在说真实项目。拿实习那套系统举例：

```
前端服务器  端口 80
后端服务器  端口 48080
```

**端口**你可以理解成一栋楼的门牌号 —— 一台电脑上可以同时跑很多个程序，靠端口区分谁是谁。

打开 `http://localhost/manage/jurisdiction` 这个页面时，实际发生了**两次**对话：

### 第一次：浏览器找前端要页面

```
浏览器  ──GET /manage/jurisdiction──→  前端（80 端口）
        ←──HTML、CSS、JS 这些文件────
```

拿回来的是一堆**静态文件** —— 页面的骨架、样式、脚本。这时候页面上很多东西还是空的。

### 第二次：页面里的脚本再去找后端要数据

页面加载完之后，页面里的 JavaScript 会**再发一个请求**，这次是找后端：

```
浏览器  ──GET /admin-api/syrk/jurisdiction/list──→  后端（48080 端口）
        ←──────────JSON 格式的数据──────────────
```

拿到数据之后，把它填进页面的表格里。**到这一刻，你才看到数字。**

> 这就是为什么打开网页时，有时候先看到框架、过一会儿数据才出来 ——
> 因为那是两次独立的对话。

## 三、后端收到请求之后，经过哪些人

后端这边不是一个函数干完所有事，而是分成了几层。用实习项目的一个真实接口举例：

```
请求：GET /admin-api/syrk/jurisdiction/list

① Controller（接待员）       JurisdictionController.java
        ↓  收到请求，认出「这是要一串权限列表」
② Service（办事的）          JurisdictionService.java
        ↓  定义「要列表」这个动作有哪些业务规则
③ ServiceImpl（具体办事的）  JurisdictionServiceImpl.java
        ↓  真正开始干活
④ dal / Mapper（仓库管理员） 去数据库里把数据取出来
        ↓
   把数据一层层往回传 → 变成 JSON → 返回给浏览器
```

**为什么要分成四层，不能一个文件写完？**

因为每层要解决的问题不一样：

| 层 | 只关心 | 不该关心 |
|---|---|---|
| Controller | 来的请求是什么格式、参数对不对 | 数据从哪来 |
| Service | 业务规则（要不要过滤、要不要权限校验） | 用哪个数据库 |
| dal / Mapper | 怎么把数据从库里捞出来 | 业务规则 |

**好处是改动不会传染。** 换数据库，只动 dal；加一条业务规则，只动 Service；改接口路径，只动 Controller。

一个文件全写完也能跑，但改一处就会牵连全部 —— 这就是「能跑」和「能维护」的区别。

## 四、怎么自己验证这条链路

不用打开浏览器也能测，用 `curl` 直接敲后端的门：

```
curl -v -H "Authorization: Bearer test1" \
        -H "tenant-id: 1" \
        http://127.0.0.1:48080/admin-api/syrk/jurisdiction/list
```

`-H` 是加一个**请求头** —— 相当于在信封上多写一行信息。上面这两行是告诉后端：
「我是谁」（`Authorization`）和「我在哪个租户下」（`tenant-id`）。

如果后端返回数据，说明**从这一层往后（Controller → Service → dal → 数据库）是通的**；
如果返回 401 或 403，说明卡在**身份验证**这一层，还没走到业务代码。

**这就是排查问题的基本方法：从中间切一刀，看哪边断了。**

## 附：`malloc` 要来的内存，不一定是干净的

写链表的时候要动态申请内存，用的是 `malloc`。有个坑要知道：

**`malloc` 只是给你一块地，不会替你把地扫干净。**

验证方法：

```c
int *p = malloc(sizeof(int) * 4);
for (int i = 0; i < 4; i++) printf("%d ", p[i]);   // 第一次打印
free(p);

int *q = malloc(sizeof(int) * 4);                  // 同样大小
for (int i = 0; i < 4; i++) printf("%d ", q[i]);   // 第二次打印
```

两次打印出来的东西**不一样**。因为 `free` 只是把地还回去，**并没有抹掉上面的痕迹**；下一次 `malloc` 很可能把**同一块地**又分给你，上面还是上次留下的值。

实测：

```
第一次：data=111  next=0xdeadbeef  prev=0xcafebabe    ← 我填的
free 之后重新 malloc 同样大小：
第二次：data=-429042753  next=(nil)  prev=0xcafebabe  ← 有的还是上次的值
```

### 这意味着什么

你申请了一块内存，里面的每个字段，**要么你自己赋值，要么它就是垃圾**。

有个真实例子：写一个双向链表，每个节点有 `data`、`next`、`prev` 三个字段。
`data` 和 `next` 都赋了值，`prev` 忘了 —— 运行起来没报错，因为那块内存刚被操作系统给你，恰好全是 0。

**但这是运气，不是保证。** 只要这块内存之前被用过，`prev` 就会是一个野地址；程序一旦沿着它往回走，就会崩在一个看起来毫无道理的地方。

### 正确的做法

**申请完内存，立刻把所有字段都赋一个明确的值。**

```
malloc 完 → 立刻把所有字段赋值（不需要用的，赋 0 或 NULL）
```

一句话：**`malloc` 只负责给你一块地，不负责那上面住的是谁。**

## 一句话版本

> **一个网页是两次对话攒出来的：一次要骨架，一次要数据。**
> **数据要经过接待员、办事的、仓库管理员三层，才回到你眼前。**
> **而 `malloc` 给你的内存，上面可能还住着上一个程序留下的东西。**
