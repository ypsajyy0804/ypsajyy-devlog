# 程序在内存里是什么样子

> 这篇笔记只讲一件事：**同一个字符串，放在不同的地方，命运完全不同。**
>
> 不需要编程基础也能读完。读完之后你会知道，为什么有些程序崩溃，是「注定」的。

---

## 一、从一个崩溃说起

有三行 C 代码：

```c
char s1[] = "hello";     // 写一：把 hello 存进一个数组
char *s2 = "hello";      // 写二：只是记下 hello 在哪儿

s1[0] = 'H';             // 第一行执行成功，s1 变成 Hello
s2[0] = 'H';             // 第二行执行，程序当场崩溃
```

两句看起来几乎一样。第一句改成功了，第二句直接把程序弄死。

**差别只有一点点：`[]` 和 `*`。**

但它们背后对应着内存里两个完全不同的地方。这篇笔记讲的就是这件事。

---

## 二、程序跑起来的时候，内存被切成了几块

先建立一个画面。

你写的 `.c` 文件是给人看的文字。要用它，得先**编译** —— 把文字翻译成电脑能执行的指令和数据，打包成一个文件。

这个文件双击运行（或者命令行跑）的时候，电脑不是把它整个塞进一块内存就完事。它会**按用途把内容分开放**：

| 这块地叫什么 | 里面装什么 | 举个例子 |
|---|---|---|
| 代码区 | 你的函数翻译成的指令 | `main` 函数的指令 |
| **只读数据区** | 写死在程序里的常量 | **`"hello"` 这个字符串** |
| 已初始化数据区 | 有初值的全局变量 | `int g = 100;` |
| 未初始化数据区 | 没有初值的全局变量 | `int g;` |
| **堆** | 程序运行中主动要来的内存 | `malloc(24)` 要来的 24 字节 |
| **栈** | 函数的局部变量 | **`s1` 这个数组** |

前四块在程序一启动就确定了大小。后两块（堆和栈）是跑起来之后才长出来的。

> 加粗的三块是这篇笔记的主角。

---

## 三、每一块都有自己的「权限」

关键是：**这六块地，不是每一块都能写。**

操作系统给每一块地设了三个开关：

- **r（read）** 能读
- **w（write）** 能写
- **x（execute）** 能执行

看一个真实程序启动后的分配表（这是 `gdb` 里 `info proc mappings` 的输出，节选）：

```
起始地址          结束地址          权限
0x555555554000   0x555555555000   r--p      ← 只读数据区（"hello" 在这）
0x555555555000   0x555555556000   r-xp      ← 代码区（能执行）
0x555555558000   0x555555559000   rw-p      ← 全局变量区（能读写）
0x555555559000   0x55555557a000   rw-p      ← 堆
0x7ffffffdd000   0x7ffffffff000   rw-p      ← 栈
```

`r--p` 的意思是：能读、**不能写**、不能执行、私有。

**为什么要设这么一道墙？**

因为只读数据区里的 `"hello"`，是**全程序共享的一份**。如果你的程序能改它，那么任何一句代码改了这个字符串，别处看到它的地方全都会跟着变 —— 程序会变得无法推理。

所以操作系统直接把这块地设成「只读」。谁想写，就当场崩给谁看。

---

## 四、回到那三行代码

现在可以解释崩溃了。

### `char s1[] = "hello";`

这一句的意思是：**给我在这块地方放 6 个字节（h、e、l、l、o、结束符），然后把 hello 拷进去。**

这 6 个字节放在**栈**上 —— 栈是可读可写的。所以 `s1[0] = 'H'` 完全合法。

**`s1` 是你自己的一份拷贝。** 你怎么改都行，不影响别人。

### `char *s2 = "hello";`

这一句完全不同。`s2` 不是一个数组，它只是一个**地址**（8 个字节，用来记住「hello 在哪里」）。

它不拷贝任何字符。它只是**指向**只读数据区里那份 `"hello"` —— 那份是**全程序共享、且不许写的**。

所以 `s2[0] = 'H'` 的意思是：

> 「找到 s2 记的那个地址，把那里的第一个字节改成 H。」

而那个地址，落在一块只有 `r--` 权限的地上。

**操作系统当场拒绝，程序崩溃。** 这个崩溃有个专门的名字：**段错误（SIGSEGV）**。

### 两句话总结

| | `char s1[]` | `char *s2` |
|---|---|---|
| 存在哪 | 栈 | 只有地址在栈上，内容在只读区 |
| 有几份 | 你自己一份 | 全程序共享一份 |
| 能改吗 | 能 | **不能** |
| 改的后果 | 正常 | **段错误，程序退出** |

---

## 五、怎么亲眼看到这件事

光听我说没用。你可以自己验证：

```
gcc -g -o test test.c
gdb ./test
```

进去之后敲三行：

```
run            # 跑到崩溃
bt             # 崩在哪一行
info proc mappings   # 把内存的分区表列出来
```

再用 `p &s1` 打印 `s1` 的地址，`p s2` 打印 `s2` 记的地址，拿这两个地址去上面那张表里对 —— 你会发现它们落在不同的行，一行的权限有 `w`，一行没有。

**这就是「亲眼看见」。**

---

## 六、知道这件事有什么用

**① 崩溃不用猜了。**
程序段错误的时候，99% 是因为它想写一块自己没有写权限的内存，或者访问了一块已经不存在的地方。知道分区和权限，就知道往哪儿查。

**② 后面所有的内存问题，都在这个坐标系里。**
内存泄漏（要了内存没还）、缓冲区溢出（写到了自己那块地之外的邻居家）、野指针（记着的地址已经失效）—— 全部是「这块地归谁、还能不能用」的问题。

**③ 面试会问。**
「字符串常量存在哪个段」「为什么 `char *s` 不能改」—— 这是 C/C++ 岗位的高频题。能画出这张分区表、能说出权限位，比背十句概念有用。

---

## 七、一句话版本

> **同一个 `"hello"`，你拷贝一份存在自己的栈上，就能改；你只是指过去，指向的是全程序共享的只读副本，改就崩。**

## 附：一个看起来能跑、其实是错的写法

顺带记一个同类的问题 —— **「跑通了」不等于「写对了」。**

打印一个类型占多少字节，常见写法是：

```c
printf("%ld\n", sizeof(int));
```

这行在 Linux 上打印 `4`，看起来完全正常。但它其实是错的。

原因：`sizeof` 返回的类型是 `size_t`（一个无符号整数类型），而 `%ld` 要求的是**有符号**的 `long`。两者类型不匹配。

**为什么碰巧对了？** 因为在 Linux 64 位上，`long` 和 `size_t` 恰好都是 8 字节，打印小数字时结果一样。

**为什么还是必须改？** 换个平台就错 —— 比如 Windows 64 位上，`long` 是 4 字节而 `size_t` 是 8 字节，会打印出垃圾值。

正确写法是 `%zu`（`size_t` 专用格式符）。

> **「碰巧对」和「对」是两件事。** 这一条以后会反复出现。
