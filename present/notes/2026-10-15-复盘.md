## 1. 一个进程的地址空间（今天的主线）

### 1.1 你那份 mappings，逐行归属

施工单问的是「一共落在几个段里」，不是「把 mappings 抄一遍」。
你抄全了表，但没写出**段的名字** —— 名字才是以后能复用的东西。

| 地址范围（B01 那次） | Perms | 这一行是谁 | 里面放什么 |
|---|---|---|---|
| `0x555555554000`+0x0 | `r--p` | ELF 头部区 | 程序头、`.dynsym`（动态符号表） |
| `0x555555555000` | `r-xp` | **`.text`** | 你写的机器码 —— `main` 的指令就在这 |
| `0x555555556000` | `r--p` | **`.rodata`** | **字符串字面量 `"hello"` 在这里** |
| `0x555555557000` | `r--p` | `.eh_frame` | 栈回溯和异常处理用的表 |
| `0x555555558000` | `rw-p` | **`.data` + `.bss`** | 有初值 / 无初值的全局变量和 `static` |
| `0x555555559000` | `rw-p` | **`[heap]`** | `malloc` 要来的内存 |
| `0x7ffff7c00000`… | `r--p` / `r-xp` / `rw-p` | `libc.so.6` | C 标准库的只读段 / 代码段 / 数据段 |
| `0x7ffffffdd000` | `rw-p` | **`[stack]`** | 局部变量、函数参数、返回地址 |
| `0x7ffff7ffb000` | `r--p` | `[vvar]` | 内核共享给用户态的时间数据 |
| `0x7ffff7fc1000` | `r-xp` | `[vdso]` | 内核塞进来的「假库」，加速系统调用 |

**要背下来的就 6 个名字：`.text` / `.rodata` / `.data` / `.bss` / `[heap]` / `[stack]`。**
剩下的都是映射进来的共享库和内核辅助区。

### 1.2 权限那几个字符怎么读

`rw-p` 拆成四部分：`r` 读 · `w` 写 · `x` 执行 · `p` 私有（private）

| 权限 | 什么意思 | 谁是这个权限 |
|---|---|---|
| `r-xp` | 能读、能执行，**不能写** | 代码段 |
| `r--p` | 只能读 | 只读数据（含字符串字面量） |
| `rw-p` | 能读能写，**不能执行** | 栈 / 堆 / 全局变量 |
| `---p` | 什么都不许 | 保护页（libc 里那条 `---p` 就是 guard page） |

> 最后一位 `p` vs `s`：`p` = private（写时复制，进程私有），`s` = shared。
> 你看到的全是 `p`，因为都是写时复制的私有映射。

### 1.3 `s1` / `s2` 的最终答案

| 是什么 | 地址 | 落在哪个段 | 权限 | 能改吗 |
|---|---|---|---|---|
| `char s1[] = "hello";` 这个数组 | `0x7fffffffd8c2` | `[stack]` | `rw-p` | 能 |
| `char *s2 = "hello";` 指向的那 6 个字节 | `0x555555556004` | `.rodata` | `r--p` | **不能 → 段错误** |
| `s2` 这个指针变量**本身** | `0x7fffffffd8b8` | `[stack]` | `rw-p` | 能（但只是让它指向别处） |

**关键区别在这里：`s2` 自己（8 字节的指针变量）在栈上、可写；它指向的那块内存在 `.rodata`、只读。**
`s2[0] = 'H'` 动的是后者 —— 改的是指针**指向的东西**，不是指针本身。

### 1.4 你笔记里写对的 / 缺的

- ✅ 你写的「字符串字面量落在可执行文件对应的只读内存映射区域」—— **这句话是对的**。缺的只是名字：叫 `.rodata`。
- ✅ `s1` 落在栈内 —— 对。
- ⚠️ 第 3 问（「以后在哪用得上」）你只举了同一个段错误的例子。
  真正的用途至少有三处，都在 `future/roadmap.md` 里：

## 2. gdb：今天用到的四个命令

| 命令 | 回答什么问题 |
|---|---|
| `run` | 跑到崩溃 |
| `bt` | 崩在哪一层调用 —— **只有一帧，是因为崩溃就发生在 `main` 自己的代码里**，栈上没有「被调用的函数」压着 |
| `info proc mappings` | 这个进程的地址空间切成哪几块、每块什么权限 |
| `p &s1` / `p s2` | 两个地址分别是多少 |
| `x/s s2` | 按字符串看一块内存 |

- `-g` 给的是**调试信息**（变量名、行号、类型）。去掉它，`bt` 只能给函数名和地址、给不出行号 —— 这就是你第 4 问的答案。
- **段错误不是「地址不对」，是「地址是对的，但这一页没有你要的那个权限」。** 今天你撞见的是后者，这个区分以后很值钱。

## 3. 格式符：为什么 `%ld` 打印 `sizeof` 是「碰巧对」

### 3.1 先解决你的追问：明明是 `size_t`，为什么报成 `long unsigned int`？

因为 **`size_t` 不是新类型，是 `typedef`**。Linux x86-64 上它就是 `unsigned long`。

10 秒自证：

```
gcc -dM -E - < /dev/null | grep SIZE_TYPE
```

输出 `#define __SIZE_TYPE__ long unsigned int` —— 编译器自己就是这么定义 `size_t` 的。
**gcc 报错时报的是底层类型，不是 typedef 的名字。** 你的这一问是对的。

### 3.2 gcc 什么时候报、什么时候不报（实测，不是背的）

两个用例，加 `-Wall -Wextra`：

| 代码 | 默认 | 加 `-Wformat-signedness` |
|---|---|---|
| `printf("%ld\n", sizeof(char));` | **不报** | 报 |
| `printf("%d\n", sizeof(int));` | **报** | 报 |

原因：

- `%ld` 要 `long`（8 字节），实参是 `long unsigned`（8 字节）—— **大小相同，只差符号性** → 默认不管。
- `%d` 要 `int`（4 字节），实参是 `long unsigned`（8 字节）—— **大小都不同** → 默认就报。

一句话：**gcc 默认比的是「大小 / 类型种类」；符号性要显式加 `-Wformat-signedness` 才管。**

### 3.3 变体练习：三行里有两行是对的（施工单里我写错了）

| 写法 | 对不对 | 为什么 |
|---|---|---|
| `printf("%zu\n", sizeof(int));` | ✅ | `%zu` 就是给 `size_t` 的 |
| `printf("%ld\n", (long)sizeof(int));` | ✅ | `(long)` 转完就是 `long`，`%ld` 匹配。**多余，但正确** |
| `printf("%d\n", sizeof(int));` | ❌ | `%d` 只读 4 字节，实参是 8 字节 —— **undefined behavior** |

**你的判断是对的。** 我那份施工单写的是「哪一行是对的？另外两行错在哪」，预设了只有一行对 —— **我错。**
（唯一要补的一句：`-Wformat` 在报错时提示的 `%ld`，只是按**大小**给的建议，不代表它「更对」。）

「多余但正确」和「碰巧打对」的区别：前者类型严格匹配，后者靠平台巧合 ——
Linux LP64 上 `long` 和 `size_t` 一样大，Windows LLP64 上 `long` 是 4 字节。**这两个词的区别就是这题 70% 的价值。**

### 3.4 第三个：`printf("%d\n", (size_t)5000000000)` 打出 `705032704`

你算的「低 32 位」是对的。补上机制：

```
5000000000 = 0x1_2A05F200
低 32 位    = 0x2A05F200 = 705032704
高位那个 1  = 被扔掉了
```

为什么扔掉：x86-64 的 varargs 约定里，实参按 **8 字节**放进寄存器；`%d` **只从里面读低 4 字节**。
高位那 32 位还在寄存器里，只是没人看。

注意 `0x2A05F200` 的 bit31 是 0（最高位十六进制是 `2` = `0010`），所以印出来是正数。
**把值换成 `4000000000`（= `0xEE6B2800`，bit31 = 1）再跑一次，`%d` 会印出负数。**
这就是「`%d` 是有符号的」这句话的可见后果。

## 4. 一句话总结（面试版）

- 字符串字面量在 **`.rodata`**（只读页面），`char[]` 在 **栈** 上（可写）；往只读页写 = `SIGSEGV`。
- `size_t` = `unsigned long`（LP64），配套格式符是 **`%zu`**。
- 格式符和实参类型不匹配是 **UB**。「在 Linux 上打对了」不叫对。
- gcc 默认不管**符号性**，只管**大小 / 类型种类**。

## 6. 补：三个卡住的点（答案直接写在这里，不用再答）

### 6.1 「段名」和「内核的权限块」是两套切法

| 谁切的 | 按什么切 | 名字长什么样 | 在哪看 |
|---|---|---|---|
| 编译器 / 链接器 | **用途**（这是代码 / 这是只读数据 / …） | `.text` `.rodata` `.data` `.bss` | `readelf -S build/B01` |
| 内核 | **权限**（r-x / r-- / rw-） | 没名字，只有地址范围和 `rw-p` | gdb 的 `info proc mappings` |

**`.text` 这些名字在 `info proc mappings` 里根本不存在** —— 那条命令给的就不是这个信息。
两套名字说的是同一批字节，只是分组方式不同。

各段放什么：

| 名字 | 放什么 | mappings 里的权限 |
|---|---|---|
| `.text` | 函数编译出来的机器码 | `r-xp` |
| `.rodata` | 字符串字面量、`const` 全局量 | `r--p` |
| `.data` | **有初值**的全局 / `static` 变量 | `rw-p` |
| `.bss` | **没初值**（或初值为 0）的全局 / `static` 变量 | `rw-p` |
| `[heap]` `[stack]` | **不是 ELF 段** —— 方括号是内核起的名，程序跑起来才有 | `rw-p` |

**两张表怎么接起来**（用 B01 验过）：

```
readelf -S build/B01   →  .rodata  Address = 0x2000
info proc mappings     →  Offset 列    = 0x2000
mappings 第一行 Start Addr              = 0x555555554000
0x555555554000 + 0x2000                 = 0x555555556000   ← r--p 那行的 Start Addr
p s2                                    = 0x555555556004   ← 就在 .rodata 里，偏移 4
```

编 PIE 时，**运行地址 = 映像基址 + readelf 给的 Address**。所以 mappings 的 `Offset` 列 ⇄ readelf 的 `Address` 列。

### 6.2 源码文件和可执行文件是两个文件

`A04.c` 和 `build/A04` 是两个独立的文件，**改一个不会动另一个**。

`ls -l` 的每一行是 7 段，第 ⑥ 段是「最后一次被改动的时间」：

```
-rw-r--r-- 1 ypsajyy ypsajyy   612 Oct 15 21:04 A04.c
-rwxr-xr-x 1 ypsajyy ypsajyy 16160 Oct 15 21:10 build/A04
│          │ │       │       │    │              │
①权限      ②硬链接 ③属主   ④属组  ⑤大小  ⑥修改时间  ⑦文件名
```

所以：`vim` 改完源码直接 `./build/A04`，跑的还是**上一次 `gcc` 产生的旧程序**。
**「改了源码」和「改了程序」之间永远隔着一次编译。** 这就是 `make` 存在的原因
（`roadmap.md` W5 会正式学它：它替你看时间戳，只重编该重编的）。

### 6.3 `else` 支的「前提」和「条件」不是一回事

- **前提** = 这个分支**依赖什么**才成立 → 它依赖「**c 是最小的**」（`else` 里第一句就是 `printf("%d ", c)`）
- **条件** = 这个依赖**被破坏时**长什么样 → `a == b` 且 `c` 比它们大（唯一一种出错情形）

他的第一答「c 最小」就是前提。补的「a、b 不相等」不是前提，是条件。
