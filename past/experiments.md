## 🔑 不用框架的实验

> 这两次实验是这份文件里最重要的内容。它们说明我在很早的时候就问出了那个关键问题：
> **框架究竟替我做了什么？不用框架，我怎么把同样的功能实现出来？**

### 用 `ServerSocket` 手写 HTTP 处理
不用 Spring，用普通 Java 的 `ServerSocket` / `Socket`，配合手写 URL 映射，试着理解一个 HTTP 请求从进来到返回，中间到底发生了什么。

- **当时的疑问**：为什么用 Spring 只要写个 `@RestController` 就行了？中间是谁在干活？
- **结果**：能跑通简单的请求响应，但对阻塞、并发、连接复用完全没有概念
- **遗留问题**：`accept()` 之后到底发生了什么？为什么一个连接会占一个线程？C10K 是什么？

### 纯 Java + JDBC，手动加载 MySQL 驱动
不用 MyBatis-Plus，也不用 Spring，直接 `DriverManager` + 手写 SQL。

- **当时的疑问**：`@Mapper` 和 `@Repository` 到底有什么区别？MyBatis 为什么不用我写实现类？
- **结果**：看懂了「连接 → 语句 → 结果集」这条基本链路
- **遗留问题**：MyBatis 的动态代理是怎么生成实现类的？连接池是什么？事务在哪一层加的？

## 系统与服务器

| 折腾过 | 到什么程度 |
|---|---|
| Ubuntu（虚拟机 + 云服务器） | 日常操作、服务管理、配置文件 |
| SSH / SFTP | 远程连接、文件传输 |
| systemd | 服务启停、开机自启 |
| UFW | 防火墙规则、放行端口 |
| Docker / Docker Compose | 镜像拉取、容器编排、端口映射、容器网络 |
| 自建 Git 服务 | 部署 + 日常使用 |
| 静态网站托管 | 部署过个人站点 |

**收获**：对「一个服务怎么跑起来」有直觉。
**没收获到的**：进程管理、网络栈、权限模型、性能分析——这些到现在还不是体系。
