## 2024（大一）

学 Java 基础语法。**摸索式学习，没有建立起连续的体系**——这是后来所有问题的根源。

当时的学习方式：跟着课程走，但很少自己动手写完整的东西。

## 2024 – 2025（大一末 ~ 大二）

AI 编程工具兴起，开始用 Claude Code 等做项目。

- 做出 2–3 个 **Spring Boot + Maven + Vue 3** 前后端分离小项目
- 模式：提需求 → AI 生成 → 配置 → 跑起来
- 结果：项目能跑，但**三层架构的业务逻辑和接口代码读不懂**

→ 复盘见 [`projects/01-spring-boot-vue.md`](projects/01-spring-boot-vue.md)

## 2025（大二）

开始接触真实工程。

- 在 GitHub 上维护一个前后端分离项目，走了一遍 Git 分支/重构/协作流程
- 用 Docker 做容器化部署：MySQL + Spring Boot + 前端容器
- **踩了坑**：环境配置文件误提交进仓库，之后学 `.gitignore` 和安全拆分提交
- 参与一个面向小学古诗词学习的智能记忆系统设计（多端 + 多角色）

→ 复盘见 [`projects/02-acg-hub.md`](projects/02-acg-hub.md)、[`projects/03-poetry-memory.md`](projects/03-poetry-memory.md)

## 2025 – 2026（大二末 ~ 大三前）

**环境折腾期。** 这段时间写代码不多，但把一堆工具用熟了：

- Ubuntu 云服务器 / 虚拟机：SSH、SFTP、systemd、UFW、Docker Compose、自建 Git 服务
- Android 设备刷机：LineageOS、TWRP、scrcpy 无线连接
- 环境工具：VMware、Miniconda、SDKMAN
- 本地大模型：Ollama；也试过用多个智能体分工做项目的设想

→ 记录见 [`experiments.md`](experiments.md)

> 回头看：这段经历让我对「服务怎么跑起来」有直觉，但**没让我理解服务为什么这样跑**。

## 2026 上半年

出现两个**转向的信号**——两次「不用框架」的实验：

1. 用普通 Java 的 `ServerSocket` + 手写 URL 映射，试着理解 HTTP 请求是怎么被处理的
2. 不用 Spring，用纯 Java + JDBC + 手动加载 MySQL 驱动，观察 Java 究竟怎么连数据库

同时开始接触 C++ 和算法概念，并开始做一个偏离传统 Web 的项目（对话驱动的 TUI 渲染器）。

> 这两次实验背后是同一个问题，也是我现在整条路线的起点：
> **框架究竟替我做了什么？不用框架，我怎么把同样的功能实现出来？**

→ 复盘见 [`projects/05-tui-renderer.md`](projects/05-tui-renderer.md)

## 2026-10-23

J03 环境那天。我给了一段含 `@Bean` 的代码让他插进去跑，他说：

> 「我并不知道这一整段代码构成的所谓『探针』是什么，这个词我第一次听；然后我就懵里懵懂地把代码 copy 上去、运行、发生你事先告诉我的报错，可是我根本不懂这个 `@Bean` 到底做了什么。」

同一天还有一次：一个方案没跑通，我立刻掉头换了一整套。他说：

## 2026-10-24

**崩溃的一晚。** 施工单题面写得简陋，他花了**不下 5 小时**在揣测题目到底要什么，其中大块时间在问 ChatGPT：

> 「今天是 1024，说实话我内心挺崩溃的，很焦虑绝望，感觉这两年真的已经算努力的了，但有时候总是会中断，导致现在还是这么菜 害」

> 「我大量的时间花在揣测你的题目意思上，你的题目写得太简陋、让人一看就懵了！」

我核对记录后指出「总是中断」与事实不符（10-16 断过一天，10-17 起连续未断），但**题面简陋是我的缺陷，他这一点是对的** —— 当天写下「题面六要素」。

## 2026-11-02

11-02 的任务 1（括号匹配），我只写了四条约束，边界、弹出、配对含义全没写。他的原话：

> 「写的是真的迷一样，我作为一个没有写过这类函数的人，完全猜不透你要我些什么，题目是让人做的，不是让人连题目都看不懂浪费时间猜的！立马修正今天的题目；加一条出题原则（我不管你是写在 CLAUDE.md 还是其它地方，每次出题必读）：必须写清楚，绝对禁止让我画半天时间去猜题意」

**这次他是对的。** 题目重写成行为表（五行，每行一个「读到什么 → 做什么」），
`CLAUDE.md` 加 §8.2「出题必须写死，绝对禁止让我猜」，共 5 条硬规则。

## 2026-11-05

11-04 的任务 2 第 2 问（`.PHONY: clean` 不写会怎样），他答「不写就不执行 `rm`」，我判 `[~]`。
他当场反问：

> 「第二问我的原话是『不写的话，make clean 命令不会执行 rm』，为什么会和『make: clean is up to date』相反？这不是证明我答的没问题吗？事实不就是没有执行删除命令吗？你到底哪里看出我答错了？」

**这次他对了一半。** 我给的实验（注释掉 `.PHONY` 再 `touch clean`）同时满足两个条件，
证不出他错 —— 实验本身有混杂变量，是我设计错了。他的原话则漏了「目录里存在名叫 `clean` 的文件」这个前提，
无条件写出来仍然不成立。补一个只动一个变量的实验（`rm clean` 后 `make clean`），`rm` 照常执行，他自己改口。

## 2026-11-06

11-06 的 `M02.c` 反复修了三轮（`arr` 被改写 → `max` 声明了没更新 → `x` 未初始化）。
收尾时为了让他说清 `char *arr[]` 和 `char **arr` 在形参位置上是不是同一个类型，我连开了三轮。他的原话：

> 「不回答，你违反了『不给额外题』的约束……对于上面一直在讨论的那处不主线知识点……无关紧要的东西，以后不要浪费我大量的时间去一轮轮让我找，你就一直像是谜语人一样要我按『题目字面』改，你直接告诉我问题是什么、怎么改不就好了？把它写进约束」

**两句话，一对一错。**

- 「不给额外题」这半他记错了：那一问一字不差地写在 `2026-11-06.md` 任务 1「必须回答」第 2 条里，他自己交的 `11.6.txt` 第 22 行也答过，属于原题面的返工，不是临时加题。当场把原文摆出来，没有让步。
- 「谜语人」这半他是对的，而且这是第三次 —— 10-15「你问的问题太绕了」、10-18「没搞懂你在 bb 什么」。为了一个支线细节连开三轮诊断实验，是浪费。
  `CLAUDE.md` 加 **§2.1 支线细节直给**：主线走阶梯，支线一段话说完；同一个支线问题最多两轮。

## 2026-11-08

11-08 的任务 2 要求「计数器必须是 `next_id` 函数体内部的 `static` 变量」，同时又要求
「`peek_id` 返回它的当前值、不递增」。他做完 `next_id` 就停下了：

> 「这一题关于『peek_id 里怎么拿到 next_id 里那个 static 变量，返回当前值，又不许递增』这些要求，
> 我认为是无解的」

**这次他是对的。** C 里函数内的名字外面根本看不见，也没有嵌套函数，两条要求互相冲突 —— 题面写死了两件做不到一起的事。
`CLAUDE.md` §8.2 第 4 条「出题人自检，至少走三个用例」我走了形式：我自己没走过 `peek_id` 这一步。
当天把任务 2 改成两个各自独立的计数器（`next_a` / `next_b`），`2026-11-08.docx` 重新生成。

**然后是第二个错，比第一个重。** 我在他已经交了作业之后把任务 2 换成了另一道题。他的原话：

> 「我已经花了这么多时间去写，验证出这个结果你居然又重新生成题目，这不是欺负老实人嘛？任务二我写了就是写了，那怕最后只是证出它是错误的，你这算是额外给题了」

**他对。** 作业交上来之后改题面，和 10-31 那次「拿后一天的施工单复审前一天的作业」是同一类 —— 只是方向相反。
处置：`2026-11-08.md` 复原成他拿到的那一版，只在任务 2 前面加一行「第 2 条要求无解，作废，不要重做」，docx 同步还原。
