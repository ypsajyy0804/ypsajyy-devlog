# 能力现状自评

> 整理于 2026-10-12 ｜ 来源：2026 年 9–10 月历次对话的复盘，经人工整理与脱敏
>
> **这是一份自评，不是考试结果。** 只有在具体任务中验证过，我才敢说「掌握」。不确定的地方我标了「待确认」。

---

## 一句话结论

**我已经不是完全没有项目经验的初学者，但我目前的独立开发能力，还没有跟上我借助 AI 所能完成的项目规模。**

我接触过的技术和做出的项目，比单纯学完几门课要丰富；但对程序运行原理、代码执行过程、系统架构的理解，存在明显缺口。这两件事不矛盾——它们恰恰是我现在最该重视的起点。

---

## 一、基本情况

- **教育背景**：信息管理与信息系统专业，大三上，2028 届
- **编程经历**：学过 Java 基础；接触 Spring Boot、Maven、MyBatis-Plus、Vue 3、TypeScript；开始学 C++
- **AI 辅助开发**：大量使用 Claude Code 等编程智能体完成项目生成、重构与交付，有真实项目经验，**但对生成代码的理解程度不够**
- **核心问题**：不满足于继续堆叠传统 Web 增删改查项目，想从「让 AI 把软件做出来」走向「理解软件为什么能运行，并能自己实现关键部分」

大学前两年我主要在摸索着学，没有建立起扎实、连续的知识体系。后来 AI 编程工具迅速发展，我通过项目获得了不少开发经验，但**传统基础学习与项目成长之间出现了脱节**。

所以我的问题不是「学得少」，而是**项目经验、工具使用能力与底层知识之间发展不均衡**。

> ⚠️ **待我确认**：早前对话中提及「为天梯赛学过 DFS、线段树、动态规划」，但我在 2026-09 自述「数据结构与算法基本从零」。这两者不可能同时成立。**在没做过实际题目验证前，我按「从零」对待。**

我目前更偏向于**认识语法、理解局部代码、借助 AI 组合功能**，还没有充分形成不依赖提示词独立完成程序的能力。

我会主动追问代码细节（比如 `getParameter()`、`trim()`、`isEmpty()` 到底做什么），这说明我在从「知道代码长什么样」转向「理解每一步为什么这么写」。但真正扎实的基础要求我能**自己写出来**、**预测不同输入的结果**、**通过运行和调试验证判断**——这三件事我还做得不够。

### 2. Java 后端与传统 Web（接触最广，项目经历最完整）

- **Spring Boot**：做过多个小型项目，了解分层架构，接触过 Controller / Service / Repository。
  ⚠️ 很多业务逻辑与接口代码主要由 AI 生成，**我自己还不能完整读懂**。
- **Maven / 配置**：能读部分 `pom.xml`，接触过依赖管理、YAML 配置、`.env`。
  ⚠️ Maven 生命周期、依赖解析、构建过程、配置加载机制，不能算系统掌握。
- **MyBatis / MyBatis-Plus / JDBC**：接触过 ORM 与数据库访问；尝试过**不依赖 Spring 的纯 Java + JDBC 程序**并手动添加 MySQL 驱动。
  这是一个有价值的进展——我开始越过框架封装，观察 Java 究竟怎样与数据库交互。
- **Vue 3 + TypeScript + Vite + Element Plus**：做过前后端分离项目，接触过模块重构与测试。
  ⚠️ 组件状态、异步请求、路由、类型系统、前后端接口契约需要巩固。
- **还接触过**：Spring Security / JWT 权限控制、`SecurityConfig` / `JwtAuthFilter` / `SecurityContext`、`@RestController` / `@RequestMapping` / `@Autowired`、`@Mapper` 与 `@Repository` 的区别、Entity 与 DTO、Servlet / Tomcat / 跨域。

我曾试图理解这条请求链路：

```
前端请求 → SecurityConfig → JwtAuthFilter → Controller → Service → 数据访问层
```

**但知道组件名字 ≠ 掌握它们。** 如果现在让我从空项目开始独立写一个带登录、权限、数据库和前端页面的系统，我仍然会在很多步骤上需要 AI 提供代码和排错帮助。

### 3. 网络 / 操作系统 / 底层

| 领域 | 接触过的内容 |
|---|---|
| HTTP | 请求、参数获取、字符编码、前后端通信 |
| Socket | 用 `ServerSocket` / `Socket` 尝试理解网络通信 |
| Servlet / Tomcat | 试图理解 Java Web 框架之下的 HTTP 处理过程 |
| Linux | Ubuntu 日常操作、终端命令、服务管理、服务器配置 |
| 数据库连接 | JDBC、MySQL 驱动、连接流程 |

我尝试过用**普通 Java 的 `ServerSocket` + 简单 URL 映射**来理解请求处理，而不是直接用 Spring Boot。这件事对我意义很大，因为它背后是一个更根本的问题：

> **框架究竟替我做了什么？如果不用框架，我怎么把同样的功能实现出来？**

不过要说清楚：**写过 Socket ≠ 掌握计算机网络。** TCP/IP、端口、连接建立、阻塞 I/O、并发、进程与线程，都需要重新建立完整认知。同样，**会在 Ubuntu 里敲命令 ≠ 掌握操作系统原理**——我目前的 Linux 经验主要是实用操作与环境维护。

### 4. 算法与计算机基础

接触过 DFS、线段树、动态规划等概念（见上方「待确认」）。这部分**更接近入门探索，而非稳定的算法能力**。

要往底层走，我需要逐步建立：数据结构与算法 → 内存与程序执行（栈/堆/指针/生命周期）→ 操作系统（进程/线程/调度/同步/IO）→ 计算机网络（TCP/IP/Socket）→ 并发与性能（锁/竞争/延迟/吞吐）。

不需要现在全学完。关键是知道**我正在做的项目真正需要哪些**，再逐步补齐。

## 三、做过的事，以及它们的真实价值

项目的价值不只在「跑起来了」，还在于**我是否理解其中的关键设计**。

### 1. 多个 Spring Boot + Vue 3 项目，以及一段实习

大学前两年借助 AI 做过两三个 Spring Boot + Maven + Vue 3 小项目，暑假在一家小型软件公司实习，按负责人给出的需求开发过一套内部管理系统。

我体验过真实交付的环节：拆解需求、生成前后端代码、配置与运行、处理问题、交付。

**但这批经历有个明显特点：我对软件交付流程的经验，暂时领先于对软件内部实现的理解。**

要把它们转化为真正的开发能力，下一步不是再生成更多同类项目，而是挑一个已有项目逐个模块搞清楚：

1. 一次前端操作会触发什么请求？
2. 请求经过哪些后端组件？
3. 数据怎样进数据库、又怎样回到页面？
4. 出错时我能否定位问题？
5. 不借助 AI，我能否独立修改一个小功能？

### 2. 一个前后端协作项目（含工程化实践）

我在 GitHub 上维护过一个前后端分离项目，涉及 Git 分支/提交/推送/重构、前后端协同、Docker 容器与端口映射、MySQL + Spring Boot + 前端容器的部署。

踩过的坑包括：**环境配置文件误提交**、`.gitignore` 与安全提交拆分、模块重构、黑盒测试与接口缺失排查。

这部分我的判断是：**有一定工程实践视野，但还需要从「知道怎么让工具跑起来」发展到「理解每个环节的故障为什么发生、怎样验证修复是否正确」。**

### 3. 一个产品设计 / 业务建模项目

参与过面向小学古诗词学习的智能记忆系统设计，涉及 Java Web、微信小程序、教师端 / 学生家长端 / 管理端，以及辅助记忆、语音朗读、背诵评分、复习安排等功能。

我认真调整过创新点表述，试图让「脑科学 / 多模态记忆 / 间隔复习」的描述与**实际实现**相匹配，而不是夸大技术能力。

这类经历体现了另一组能力：把模糊需求拆成模块、理解不同用户角色与权限、思考真实使用场景、**识别技术方案与宣传描述之间的边界**。

### 4. 一个正在做的个人项目：对话驱动的 TUI 图形渲染器

这是目前最偏离传统 Web 的项目——目标不是做聊天界面，而是**根据聊天话题生成相关画面并持续运行动画**。

接触到的问题分层：

| 层次 | 问题 |
|---|---|
| 一 | 理解对话 —— 让模型把话题转成机器可执行的场景描述 |
| 二 | 生成画面 —— 场景描述 → 颜色 / 图形 / 文字 / 布局 |
| 三 | 让画面持续运动 —— 随时间变化产生动画，而不是每帧重画一张静态图 |
| 四 | 实时运行 —— 控制帧率、延迟、绘制成本与状态更新 |

此前讨论过一条路径：先学浏览器端 JavaScript、Canvas 2D 和 `requestAnimationFrame`，建立「实时动画 + JSON 场景状态」，再接入 AI；WebGL / WebGPU 后置。

**必须承认：我对这类图形系统的认识还处在建立阶段。** 它更像一块学习新领域的实验场，不是我已有的技术优势。

## 五、我的知识结构（这部分最重要）

### 第一层：工具与应用层 —— 相对较强

使用 AI、搭项目、跑程序、配环境、部署服务、组织模块。
这是我最熟悉的层次：**能借助现成框架与 AI，比较快地把项目从需求推到可运行。**

### 第二层：软件实现与架构层 —— 正在建立

理解接口、调用链、模块职责、数据流、程序状态、错误处理。
我认识不少架构概念，但对业务代码的**执行过程**还不够熟。看懂部分配置 ≠ 能解释整个系统的行为。

### 第三层：计算机原理与机制层 —— 需要系统补齐

数据结构、操作系统、网络协议、内存、并发、渲染机制、性能分析。
**这是我目前最明显的缺口。**

我尤其要强调一点：**我的问题不是「只会用高级框架」，而是还没把框架里的抽象概念，与自己能理解的具体执行过程对应起来。**

- 我知道 Spring Boot 能接收 HTTP 请求 → 但请求怎样进入服务器、怎样匹配到 Controller？
- 我知道 MyBatis-Plus 能操作数据库 → 但 JDBC、SQL 执行、连接、结果映射是怎样的？
- 我知道 Docker 能跑服务 → 但容器进程、网络、文件系统、端口映射是什么关系？
- 我想让画面持续运动 → 但画面为什么需要不断刷新、每一帧怎样计算、瓶颈在哪里？

**当这些对应关系建立起来，我学新技术时就不会每次都从头开始。**

## 六、优势与短板

### 已经具备的

1. **有实际项目经验，不只是课程练习。** 接触过实习交付、前后端分离、代码仓库、部署和真实需求——这些可以成为学原理的载体。
2. **愿意追问底层原因。** 主动追问过 Servlet、Socket、JDBC、XPath、JSONPath 等问题，不满足于知道名词。
3. **工具探索意愿强。** 从 Claude Code、多智能体到 Linux 服务器、Docker、Android 刷机，都愿意亲自试。
4. **开始主动审视路线。** 已经意识到单纯靠提示词生成增删改查系统不构成技术竞争力，开始关注系统编程、图形渲染等更感兴趣的方向。

### 最值得解决的

1. **独立编程能力尚未验证。** 能通过 AI 完成项目 ≠ 能独立完成同类任务。**缺少「自己写、自己调、自己解释」的量。**
2. **计算机基础零散。** 接触过不少概念，但没形成从程序 → 操作系统 → 网络 → 应用框架的完整地图。
3. **阅读代码能力弱。** 面对真实业务逻辑时，难以追踪数据从哪来、经过什么、产生什么结果。
4. **方向容易发散。** Java、C++、Linux、Rust、Go、嵌入式、图形渲染都值得看，但同时推进会每个都停在「认识名词」。
5. **缺少可验证的能力基准。** 目前靠项目完成情况判断进步，缺少一组不依赖 AI 的编程/调试/原理解释任务来验证真实程度。

> 这些不代表我不适合做技术。它们意味着：**我现在最需要的不是扩大接触范围，而是把已有经验变成可独立使用的知识。**

## 七、自检清单

不推荐用「我会不会 Spring Boot」这种笼统问题评价自己。改看能不能完成这些任务：

| # | 能力 | 判据 | 状态 |
|---|---|---|---|
| 1 | **独立编程** | 不复制 AI 生成的完整代码，独立写出一个小功能，并解释每个关键步骤 | ☐ |
| 2 | **阅读代码** | 从一个入口开始，追踪请求、数据处理、返回结果的完整过程 | ☐ |
| 3 | **调试能力** | 遇到异常时，能通过日志、断点、最小复现逐步定位原因 | ☐ |
| 4 | **原理解释** | 不背术语，能用自己的话解释程序为什么这样运行 | ☐ |
| 5 | **系统设计** | 能说清模块职责、数据如何流动、为什么选某个方案 | ☐ |
| 6 | **性能判断** | 能区分功能正确 / 运行流畅 / 资源合理，并通过测量而非猜测优化 | ☐ |

**只有在具体任务中验证过才勾选，不确定就留空。**

真正重要的进步不是从「会用 Java」变成「会用 C」，而是从「需要 AI 帮我把程序写出来」，逐步变成「我知道程序应该怎样运行，能独立实现关键部分，也能判断 AI 给的方案是否合理」。

## 八、总体评价

> 我是信息管理与信息系统专业的大三学生，有一定 Java Web 项目开发、AI 辅助编程、Linux 环境维护和软件部署经验。我能借助 AI 编程工具完成一定规模的应用开发，也接触过前后端分离、数据库、接口、权限控制和容器化部署。
>
> 但由于前两年缺少连续、系统的基础训练，**我的项目实践经验领先于底层原理理解与独立编程能力**。对真实业务代码、程序执行流程、网络通信和系统运行机制，我需要通过阅读代码、手动实现、调试和原理学习逐步补齐。
>
> 我正在从传统 Web 应用开发转向更关注程序运行机制与系统技术的方向。**首要任务不是掌握更多技术名词，而是建立扎实的编程与计算机基础，并以实际项目为载体，把知识转化为可验证的独立开发能力。**

前两年确实有些基础没打牢，但我**不是从零开始**：我见过真实项目的复杂性，踩过环境和部署的坑，也已经开始意识到自己究竟不懂什么。这份经验有价值，只是需要重新组织。

接下来最值得做的：**缩小学习范围、加深理解程度，让每一个项目都反过来提升我的计算机基础。**
