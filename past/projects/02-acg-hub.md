## 这是什么

一个前后端分离的 Web 项目。技术上和项目 01 是同一类东西，**但这次我走了一遍真正的工程流程**——这是我目前最有价值的一段经历。

## 我实际做了什么

**我自己做的：**
- **Git 流程**：分支、提交、推送、代码重构
- **容器化部署**：写 `Dockerfile` / `docker-compose.yml`，把 MySQL、Spring Boot 后端、前端容器编排起来
- **端口映射与服务连通**：排查过容器之间连不通的问题
- **前端模块重构**：面向教师模块的重构
- **黑盒测试与接口排查**：测出接口缺失、对不上契约
- 处理 `.gitignore`，把误提交的配置从版本库拆出去

**AI 生成、我只是跑通的：**
- 后端业务逻辑
- 大部分前端组件实现

## 踩过的坑

| 现象 | 怎么发现的 | 根因 | 解决了吗 |
|---|---|---|---|
| **环境配置文件被误提交进仓库** | 检查提交内容时发现 | 没配 `.gitignore` | ✅ 补齐并做了安全拆分提交 |
| 容器起来了但服务连不通 | 请求超时 | 容器网络 / 服务名解析 / 端口映射 | ✅ 试出来的 |
| 前端请求后端 404 | 浏览器网络面板 | 接口路径不一致 / 代理配置 | ✅ |
| 接口返回结构和前端预期不符 | 黑盒测试时发现 | 前后端契约没对齐 | ✅ 但**是靠人工比对发现的** |

## 学到了什么

这段经历涉及的已经不只是语法，而是**软件工程**：

- 版本控制不只是 `git add . && git commit`——**要有意识地控制提交内容**
- 容器化部署的**实际操作**（镜像、容器、端口、网络、编排）
- 前后端协作里，「接口契约」是一个真实存在、会出问题的东西
- 测试可以发现功能缺陷，但**发现不了设计问题**
